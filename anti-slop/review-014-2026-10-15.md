# Contributor tiers and Owner editing

Reading this as: REL community credits grouped into Owners, Developers, Reviewers and Rankers, using AREDL's grouped-name pattern with REL's existing dark green surfaces, original logo, Red Hat Text and lime accent. ENERGY 1 / RHYTHM 1 / MOTION 1. The user confirmed the original assignments and requested editable credits; the later instruction to do it authorized the proposed Owner editor.

## Block 1: Hard Gate

PASS. The homepage has four named sections in the requested order. It preserves the original four credits and stable profile links, with an honest empty Reviewers state. The strongest green treatment identifies Owners; every tier has a text heading, so color and icons are supplementary. No new person, account ownership, portrait, statistic or testimonial is invented. Credits work before people register accounts.

Public loading, empty, error and retry states are implemented. Saved records supply names and tier membership; hidden credits do not reappear through a hard-coded public fallback. Owner forms have labels, grouped tier checkboxes, status text, visible focus and 44px controls. The native form validates names, and the server checks every saved field again. The editor preserves unsaved drafts across tab changes, warns when leaving with edits, and retains drafts after failed saves. Stale drafts require a reload instead of overwriting other changes.

## Block 2: Purpose-Gate

PASS. Stacked tiers communicate the requested contribution hierarchy. Compact name links follow AREDL's grouping pattern while retaining REL's own surfaces, typography and arrow treatment. Crown, code, checked-document and ranking icons reinforce the role headings. Owner green emphasis reflects the tier's position; quieter tiers use readable neutral text. Mobile places headings above names, intermediate widths use a narrower heading column and wide layouts add breathing room. There is no new decorative gradient, glow, shadow or continuous animation.

The Admin Contributors section groups public credits separately from account access permissions. Tier checkboxes express multi-tier membership. Move buttons provide a keyboard alternative to dragging, and hiding retains credits for restoration. Explicit Save contributors publishes the draft together; account linking continues through the existing verified Users & roles controls.

## Block 3: Liveliness

PASS. The dials and design direction were declared before implementation. The original REL identity remains, with role order and green owner emphasis providing a clear focal point. Whitespace separates tiers without large empty hero treatments. Subtle link lift/arrow movement responds to interaction and is removed for reduced motion. Contributor groups and editing fields are driven by actual content, not filler cards or activity feeds.

## Block 4: Craftsmanship and quality

PASS. Forty-five automated checks, static build, Functions compilation and the existing full Chromium regression passed. Targeted checks cover homepage tiers and all original profile links at 320/390/560/620/768/850/1024/1440px, keyboard navigation, reduced motion and long-name wrapping. The Owner browser flow covers four widths, live homepage updates, multi-tier assignment, draft retention, ordering, hiding/restoring, adding a credit without an account, validation, failed-save recovery, stale/link conflict handling, reload and account-link navigation. Desktop/mobile previews were visually reviewed using local fixture data and genuine local fonts.

Computed contrast: lime on the Owner surface 12.90:1, member text on its link surface 16.17:1, and control borders 3.87:1 against that surface. Other text/focus colors retain the established checked palette. Text exceeds 4.5:1 and interactive boundaries exceed 3:1. No external asset dependency was added.

The additive migration and checked RPCs enforce Owner access, preserve stable IDs and account links, audit changes and use a separate contributor revision. Tests verify that rankings, their revision and account permissions remain unchanged. The migration was applied only to isolated local databases. Production application must precede merge/deployment through authenticated Supabase access; no production credentials, data changes, merge or deployment are part of this implementation.
